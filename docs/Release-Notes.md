# WordRoots 0.9.1

**这一版修的是"数据会不会丢"和"门禁会不会骗人"。** 测评历史改由 SQLite 权威，保存/清除都要等数据库确认；
标签构建必须自己跑完整门禁，不再借用主干的历史绿灯。上一版见 [`releases/v0.9.0.md`](v0.9.0.md)。

## 一、测评数据：SQLite 是唯一权威

此前页面读的是 localStorage 镜像，写库是不等待结果的异步调用——用户看到"保存成功"时，数据可能还没落库。
现在：

- 桌面版启动即 `assessment_list` 读取；页面有**加载中 / 成功 / 失败（带重试）**三态，失败时不会把"读不到"显示成"没有记录"。
- 保存与清除都**等待数据库确认**；失败给出可重试的错误，**不会**出现"保存成功"。
- 迁移、保存、清除之间互斥：迁移未完成不显示空历史；迁移中点清除不会被写回。
- localStorage 为空而库里有数据时，历史照常全部显示（本轮验收重点之一）。
- 旧数据一次性导入仍然幂等，失败不写标记、下次重试。

`assessment-persistence.test.ts` 覆盖九种场景：库有页无、页有库空、两边都有、保存失败、迁移中清除、
`item_bank_version` 往返、损坏 payload、幂等迁移、恢复后读取。

## 二、发布门禁：标签必须自证

0.9.0 的 tag 构建成功，而**同一 SHA 的 CI 曾因课程 bundle 过期失败**——发布门禁借用了另一个提交的绿灯。

- `ci.yml` 改为可复用（`workflow_call`），`portable-windows.yml` 增加 `gate` 作业并让 `build` 依赖它。
  标签构建现在在**自己的提交**上跑：类型检查、ESLint、单测、课程校验、索引、bundle、课时审计、
  词条状态、文档一致性、审校、**许可与版权**、前端构建、Rust check/test。
- 新增 `scripts/check-license.mjs`：LICENSE 与 `package.json` 必须同为 MIT；每个登记来源必须有
  role、来源说明和**权利声明**。补这道检查时发现 **S3/S4/G1/LEX 四条来源根本没有权利声明**——现在都有了。
  脚本明确写出它只查引用元数据，查不出改写/抄袭。
- `docs/REVIEW_AUDIT.md` 由脚本按 `package.json` 版本生成，CI `--check`：标题写着 0.8.0、数字是 0.9.0 的
  情况不会再出现。

## 五、本轮查出的真错误

1. `cx-terr` 的 note 抄成了 `cx-terr-2`（terrere「使害怕」）的内容——两个同形异源词根被写反。
2. `rx-stru` 的释义只写"建造"，L&S 首义是"层层堆叠、排列"，建造是引申。
3. `cx-leg` 引了 S1 第 274 页，但教材附录根本没有 `leg/lex` 条目——引用已撤下，改为全部引词典。
